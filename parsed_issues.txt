**TYF-EXR-APP** 

**Description:**

This viewport represents the deep execution layer where the child engages directly with the individual cognitive **exercises** packed inside an active lesson node. The layout operates text-free, functioning as a polymorphic interaction template.

Crucially, the rendering engine dynamically adapts to the **Exercise Access Lock** bit inherited from the master configuration:

* **Asynchronous Mode (Is_Locked == False):** Renders all exercise nodes inside the active lesson as an open carousel or horizontal grid of interactive challenge cards. The child has full cognitive autonomy to select, play, and solve any exercise in their preferred order.
* **Sequential Mode (Is_Locked == True):** Forces a rigid linear pipeline. The interface isolates exactly one exercise asset onto the active workspace container, completely blocking or blurring subsequent challenge cards until the active index sets its terminal success flags.

**Pre-conditions:**

* The child profile has successfully launched an active or unlocked lesson node via the **Primary Journey Canvas** (`TYF-LPN-APP`).

**Main Flow:**

3. **Branch 1 — Asynchronous Grid (Free Choice):**

    * The screen renders an array of open, animated exercise node entry cards side-by-side.
    * The child taps any available exercise card to launch its internal mini-game loop.
    
4. **Branch 2 — Sequential Workspace (Linear Progression):**

    * The system evaluates the child's local ledger history to find the first incomplete index item (Indexn​).
    * The screen initializes Indexn​ into full focus, while rendering future indices as locked or hiding them to maintain structured clinical focus.
    
5. The application detects the polymorphic **Exercise Type** (Image Selection, Matching, Ordering, or Distinguishing) and prepares the matching touch gesture listeners.
6. The child interacts with the screen elements (Tapping, dragging, chronological sorting).

9. **State Resolution Routing:**

    * _In Asynchronous Mode:_ The child is brought back to the exercise grid canvas, showing a green checkmark or glowing badge over the completed exercise card.
    * _In Sequential Mode:_ The interface automatically slides the completed index out of frame and executes a smooth physics transition to reveal the next unlocked exercise item (Index+1​).
    
10. Upon resolving the terminal completion validation rule for all exercises bound within the active lesson scope, the engine hands over runtime focus to the **Gamified Reward Unlock Loop** (`TYF-LPN-APP`).

**Deep Core Gesture & Asset Interaction Logic:**

1. **Image Selection (اختيار الصور)**

* **Media Architecture:** Displays 1 locked success asset (`Correct_Object_Target`) randomized amongst a variable layer of distractors (`Distractor_Objects_Pool`), scaling from 2 to 5 items based on severity setup.
* **Touch Event:** A clean single-tap boundary checker. Tapping the correct coordinate triggers immediate haptic feedback, while tapping a distractor launches a temporary passive wobble.

2. **Matching (التوصيل والمطابقة)**

* **Media Architecture:** Generates two vertical parallel streams (Column_A vs. Column_B).
* **Touch Event:** Tracks a continuous `MotionEvent.ACTION_MOVE` line from an item origin bounding box to its matching recipient block. If a line is drawn incorrectly, the line canvas snaps back like a rubber band to invite a clean retry.

3. **Ordering (التدريب التسلسلي ورسم الخطوات)**

* **Media Architecture:** Spawns a scrambled row of high-contrast action frames above empty index slot boxes (1→2→3…).
* **Touch Event:** Multi-axis drag-and-drop gesture loop. The app monitors spatial drop boundaries; placing an image card over its matching absolute sequence index triggers a gravity snap anchor, locking the card permanently into its correct position.

4. **Distinguishing (استخراج العنصر المختلف)**

* **Media Architecture:** Multi-item matrix mapping matching categories, with exactly one card featuring a broken semantic rule trait.
* **Touch Event:** Immediate single-tap vector look-up. Selecting the anomaly breaks the card pattern with a satisfying popping sound stream.

**Alternative Flows:**

* **AF-1 — Mid-Exercise Session Disruption / Interruption:** If a child abandons an exercise halfway or turns off the screen before completing it:

    * _If Unlocked (Asynchronous):_ The temporary interaction state is cached locally; returning to the hub keeps their choices preserved, allowing them to jump into a different task fluidly.
    * _If Locked (Sequential):_ The app freezes layout context tracking. Upon app wake-up, it re-initializes on the exact same incomplete index Indexn​, preserving the structured clinical pathway.
    

**Post-conditions:**

* Granular performance logs (Total attempts, coordinate accuracy, and completion duration timestamps) are committed directly to the sandboxed SQLite transaction layers.
* Local database state changes trigger reactive pipeline updates (`Room LiveData / Flow`), notifying the master journey status bars to adjust progress bars instantaneously.
* The system schedules a background workers synchronization pass to upload execution deltas to the Specialist Monitoring Center (`TYF-LPN-03`).

TAYF-75 - Child Learning Plan Execution Interface 
## **Child Learning Plan Execution Interface**

**TYF-LPN-APP** 

**Description:**

This feature defines the core, gamified interactive mobile interface presented to the child profile on their client device. Rather than enforcing a universally linear path, the application dynamically reads the multi-tier **Progression Access Locks** (Locked/Sequential vs. Unlocked/Asynchronous) configured during blueprint creation.

The application renders a highly visual, fluid, text-free interface tailored to the child's autism severity level. It selectively restricts or opens navigation components down to the individual goal, lesson, and exercise level, allowing the child free interactive traversal across unlocked nodes while holding strict structural gating only over nodes explicitly designated as sequential.

**Pre-conditions:**

* The child profile has an active plan successfully bound to their account via the backend junction table (`Child_Plan_Assignments`).
* The mobile device is authenticated and initialized under the active child session context.
* The system has localized and cached the multimedia asset bundles (Images, Audios, GIFs) required for the active or unlocked available nodes.

**Main Flow:**

1. The child opens or switches to their profile dashboard on the mobile application.
2. The system queries the local data cache (`SQLite / Room DB`) to determine the full deployment state tree and the active progress ledger:  
  Current Progress Tree=∑(Goali​→Lessonj​→Exercisek​)
3. The application renders the **Primary Journey Canvas**, parsing the dynamic access matrix flags:

    * **If a node has Is_Locked == True:** It checks for preceding chronological completion markers. If prerequisites are missing, it renders the node with an organic padlock asset graphic and blocks input events.
    * **If a node has Is_Locked == False:** It renders the item as instantly open, interactive, and available for engagement, skipping chronological checks.
    
4. The child taps any available or active flashing **"Play Session"** gateway asset to launch the respective exercise layout.
5. The interface morphs into the text-free **Polymorphic Activity Portal**, reading the specific exercise rules and its individual progression lock state (whether items within the exercise must be solved linearly or can be tapped out-of-order).
6. The child interacts step-by-step with the screen objects through tactile gestures (Tapping, dragging-and-dropping, sorting).
7. Upon passing the specific activity conditions, the system logs the session data. If a rewards package token is attached to this specific lesson index, the **Reward Asset Gateway Container** flips open dynamically on screen, discharging the asset (sound clip, token, or high-contrast GIF).
8. The mobile application writes a completed row into the local transaction ledger. If adjacent elements are sequential, it updates their locked states to active. It synchronizes all state metrics asynchronously with cloud systems (`TYF-LPN-03`) and smoothly transitions back to the main journey roadmap.

**Detailed Mobile Interaction Models per Activity Type:**

1. **Image Selection (اختيار الصور)**

* **On-Screen Execution Landscape:** The screen populates one targeted correct vector card mixed into a fluid layout containing randomized, sensory-appropriate distractor image objects.
* **Child Interaction Mechanic:** The child identifies and taps the target object. Tapping the correct item triggers a high-frequency sparkle effect, freezes further multi-touch input, writes a success log, and transitions into the next available container.

2. **Matching (التوصيل والمطابقة)**

* **On-Screen Execution Landscape:** The interface splits symmetrically into two mismatched vertical item rows (animals vs. their respective home environments).
* **Child Interaction Mechanic:** The child touches an object icon from Column A and performs a continuous drag-and-drop stroke to connect it with its partner item in Column B. When coordinates meet the correct bounding matrix, a colorful vector neon line links them permanently.

3. **Ordering (التدريب التسلسلي ورسم الخطوات)**

* **On-Screen Execution Landscape:** Presents a scrambled horizontal grid of behavioral narrative flashcards showing step-by-step routine timelines.
* **Child Interaction Mechanic:** The child physically grips, slides, and drops the scrambled frames into empty slot placeholders ordered left-to-right. The interface applies gravitational snapping physics when a card is positioned in the correct placeholder coordinate slot.

4. **Distinguishing (استخراج العنصر المختلف)**

* **On-Screen Execution Landscape:** Displays a symmetrical dynamic matrix layout of items sharing identical semantic traits, with exactly one single anomaly object breaking the pattern rules.
* **Child Interaction Mechanic:** The child inspects the pattern, scans the visual layout, and directly taps the non-conforming odd-one-out element. Correct selection breaks the anomaly card apart with a pleasant visual pop effect to signal completion.

5. **Audio Flashcards (بطاقات النطق التفاعلية)**

**Media Architecture:** Loads one target visual asset (Correct_Object_Target) paired with one audio source resolved from either a custom binary upload path or a system audio registry string identifier (System_Audio_Registry_ID). The audio source is resolved at runtime from the cloud asset bucket.

**Touch Event:** Single-tap boundary checker on the flashcard image container. Tapping the graphic triggers the audio playback engine. The system fires the mapped audio stream and logs an Audio_Playback_Event record containing: Flashcard_ID, Timestamp, Playback_Duration, and Child_Profile_ID.

* In Asynchronous Mode: The child may tap any available flashcard in the grid in any order. Each card independently logs its playback event and shows a completed badge upon trigger.
* In Sequential Mode: Only the current active flashcard is tappable. The next card unlocks only after the audio playback event for the current card is written to the local SQLite transaction layer.

6. **Instructional Video (الفيديو التعليمي)**

**On-Screen Execution Landscape:**The interface displays an embedded instructional video player directly inside the exercise screen, accompanied by simple playback controls suitable for children. The video occupies the primary interaction area, allowing the child to focus on the demonstrated activity or behavior without leaving the application.

**Child Interaction Mechanic:** The child watches the instructional video directly within the application. The video can be replayed whenever needed during the exercise. Once the required viewing criteria are satisfied, the system records the completion event, logs the viewing activity, and enables progression to the next exercise according to the configured workflow.

**Dynamic Multi-Tier Progression Constraints:**

* **Goal Level Logic:** If the active plan template has Goal 1 and Goal 2 flagged as Unlocked, the child can toggle tabs on their screen freely and engage with both developmental tracks simultaneously. If Goal 2 is marked as Locked, it remains visually frozen behind a gateway track until Goal 1 hits its 100% completion threshold.
* **Lesson Level Logic:** Within any accessible goal, lessons marked as Unlocked display active icons immediately. If a sequential lock is enforced by the Admin, the mobile layout enforces a strict index roadmap (1→2→3), where Lesson 2 ignores user touch completely until Lesson 1 writes its terminal completion code.
* **Exercise Level Logic:** Inside the activity portal, an Unlocked state allows the child to click and solve multiple displayed exercise cards in any preferred psychological pattern. A Locked state forces strict screen card pacing where the interface isolates cards into distinct, linear steps.

**App Interface Components & Behavioral Constraints:**

| **Interface Element** | **Screen Layout Mapping** | **Processing Constraints & Client-Side Behavioral Rules** |
| --- | --- | --- |
| **Primary Journey Canvas** | Main App Home Dashboard | Entirely text-free workspace; navigation relies on clear visual spatial mapping paths.  Only nodes with verified open active flags or `Is_Locked == False` state parameters respond to touch inputs. |
| **Progress Tracking Meter** | Top Sticky Status Ribbon | Displays an organic filling element (e.g., a liquid bar, growing plant, or star track) that visually matches the overall plan execution progress ratio calculated locally. |
| **Polymorphic Activity Portal** | Active Screen Layer Full View | Completely disables external phone system gestures, back navigation rails, and phone status bars to preserve concentration focus.  Dynamic layout adjusts immediately to process either rigid step-by-step screen iterations or open multi-card tapping arrays based on exercise lock bits. |

**Mobile Business Rules & Runtime Sandboxing:**

* **Asynchronous Offline Capabilities:** If connection links to the core cloud database drop while a child is interacting with a lesson node, the mobile app transitions seamlessly to local processing mode. All exercise logs, trial metrics, and reward unlock codes are committed straight to the local `SQLite / Room` transaction layer. No progress is lost, and metrics auto-sync with the administrative backend (`TYF-LPN-03`) immediately upon internet re-establishment.
* **Dynamic Rule Hot-Swapping Adaptation:** In alignment with `TYF-LPN-04`, if an Admin logs into the portal and changes a future unexecuted milestone from Locked to Unlocked, the mobile client intercepts this data flag change during background sync cycles. The interface dynamically updates the target component shell—removing padlock graphics and unlocking user access instantly mid-phase without interrupting the child's local user profile session.
* **Sandbox Data Protection Guarantee:** All completed milestones and earned rewards captured during mobile sessions are written as permanent, unchangeable database transaction records. If a global admin modifies a master template afterward, the child’s local device app ignores those mutations for completed segments, ensuring a completely stable, glitch-free clinical journey.

**Alternative Flows:**

* **AF-1 — Child Incorrect Selection / Fatigue Loop:** If a child inputs an incorrect selection coordinate or misplaces a matching line during an exercise:

    * The interface plays a soft, non-punitive, neutral visual wobble effect (No aggressive alarm or buzzing sounds to prevent sensory overload).
    * The item cards reset gently to their initial slots, prompting a calm retry tracking frame without locking the device workflow.
    

**Post-conditions:**

* The system successfully tracks and saves granular cognitive interaction metrics with zero data regression.
* Completed lesson timestamps are recorded locally, triggering a synchronization script that pipes live tracking metrics to the Specialist Progress Hub (`TYF-LPN-03`).
* The client device unlocked asset wallet index updates to include the newly earned reward media tags.

**Description**

This use case governs the structural presentation and dynamic layout of the primary "Home" dashboard interface immediately following a successful login or session restoration. It consolidates active child profiles, quick-access operational cards, personalized learning plan summaries, gamified progress rings, and system notifications into a centralized feed layout.

**Pre-conditions:**

1. The user has successfully authenticated and holds a valid session token (JWT).
2. The client device is connected to the internet (or loads the last cached structural snapshot if offline navigation is active).
3. At least one child profile is linked to the user’s account record.

**Main Flow:**

1. The user launches the application or successfully authenticates, triggering the routing engine to target the core structural interface stack.
2. The application client issues secure HTTPS GET requests to fetch the user's active context dashboard payload (including linked child profiles, daily progress metrics, and recommended activities).
3. The server validates the active authorization header, reads the backend data tables, and returns a `200 OK` JSON response containing payload attributes.
4. The application renders the **Home View Layout**, displaying the Child Profile Switcher, Active Learning Plan Tracker, and Daily Recommendation Modules.
5. The system initiates the background rendering of localized progress metrics, calculating visual vector fill metrics for circular percentage containers.

**Alternative Flows:**

**Alternative Flow C: Learning Plan Grace Period Expired (Subscription Paywall Trigger)**

## **View Learning Plan & Subscription Gateway**

**TYF-AUT-09**

**Description**

Forces the parent to review the child's tailored read-only learning plan generated from the baseline assessment. The plan remains accessible for a restricted grace period (System Configuration: **Defined by admin in settings**). Once this retention period expires, the system automatically triggers a hard cryptographic block, obscuring the plan data parameters from the parent interface and making full subscription activation a mandatory prerequisite to regain application access and view any plan structures.

**Pre-conditions**

* The parent is successfully logged in.
* A structured learning plan has been officially committed by the specialist (`UC-ADM-05`).
* The system has stamped a `Plan_Creation_Timestamp` upon plan finalization.

**Main Flow**

1. The parent navigates to the **"Learning Plan"** workspace hub or is automatically redirected here post-assessment.
2. The system checks the active child context via the **Child Context Selector Modal**.
3. The system executes an operational validation, tracking the delta time:  
  Δt=Current_Timestamp−Plan_Creation_Timestamp
4. The system evaluates the age of the learning plan ledger:

    * **Scenario A (Within Grace Period - Δt≤Defined by admin in settings):** The system grants read-only clearance. It displays the plan layout grid along with a dynamic **Grace Period Countdown Timer** and the **Action Decision Panel** (Subscribe vs. Skip). _(Proceed to Step 5)_.
    * **Scenario B (Expired Grace Period - Δt>Defined by admin in settings):** The system blocks data drawing, activates the **Plan Expiration Blackout Screen Layout**, obscuring all goals and exercises, and renders an absolute subscription block interface. _(Route directly to Step 9)_.
    
5. Below the open plan presentation layout, the parent evaluates their commercial preferences:

    * **Pathway A (Subscribe to Plan):** The parent clicks **"Subscribe to Unlock Full Plan"**. The system routes the layout directly into the checkout/online payment gateway framework (`TYF-PAY-01`). _(End of Flow)_.
    * **Pathway B (Skip Integration):** The parent clicks the secondary skip trigger link. _(Proceed to Step 6)_.
    
6. The system intercepts the skip command and overlays the mandatory **Limited Access Warning Pop-Up** on top of the viewport.
7. The parent acknowledges the restrictions by tapping **"Proceed with Limited Mode"**.
8. The system sets the active user session status to "Freemium/Limited" and routes the parent directly to the primary **Application Home Screen Layout**. _(End of Flow)_.
9. **\[Expired Block Execution\]:** The parent views the locked state interface, displaying the **Expired Plan Action Button**. The parent must tap **"Subscribe Now to View Plan"** to instantiate the Online Payment workflow; all alternative "Skip" functionalities are permanently removed.

**Alternative Flows**

* **A1 - No Active Learning Plan Found:** If the specialist hasn't finalized the plan template yet, the system blocks the execution and surfaces a pending state dashboard workspace.
